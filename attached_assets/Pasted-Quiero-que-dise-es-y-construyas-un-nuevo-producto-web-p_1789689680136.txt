Quiero que diseñes y construyas un nuevo producto web para **Caribbean Business** llamado:

# Puerto Rico Economic Dashboard
### Powered by Caribbean Business

El objetivo es crear una plataforma moderna de inteligencia económica de Puerto Rico que consolide datos públicos de múltiples fuentes gubernamentales y los presente de una manera visual, rápida y fácil de entender.

No quiero simplemente un dashboard administrativo con cards. Quiero que se sienta como un **producto editorial premium de inteligencia económica**, inspirado conceptualmente en productos como Bloomberg, Reuters, Financial Times y dashboards económicos modernos, pero manteniendo una identidad propia de Caribbean Business.

## 1. OBJETIVO DEL PRODUCTO

El usuario debe poder entrar y, en menos de 30 segundos, contestar:

**“¿Cómo está la economía de Puerto Rico ahora mismo?”**

El dashboard debe combinar:

- Indicadores económicos
- Series históricas
- Comparaciones
- Tendencias
- Insights automáticos
- Fuentes verificables
- Contexto editorial
- Eventualmente análisis mediante AI

Debe ser extremadamente rápido, responsive, SEO-friendly y diseñado principalmente para web pública.

# 4. IMPORTANT DATA RULE

DO NOT hardcode economic numbers into frontend components.

Create a normalized data layer.

Every economic observation should follow a model similar to:

```typescript
interface EconomicObservation {
  indicatorId: string;
  name: string;
  date: string;
  value: number;
  unit: string;

  frequency:
    | "daily"
    | "weekly"
    | "monthly"
    | "quarterly"
    | "annual";

  geography: string;
  source: string;
  sourceUrl?: string;

  seasonallyAdjusted?: boolean;

  previousValue?: number;
  momChange?: number;
  yoyChange?: number;

  updatedAt: string;
}
```

Create separate metadata for indicators:

```typescript
interface EconomicIndicator {
  id: string;
  name: string;
  shortName: string;
  description: string;
  category: string;
  unit: string;
  frequency: string;

  source: string;
  sourceUrl: string;

  methodology?: string;

  higherIs?: "positive" | "negative" | "neutral";
}
```

The frontend should only interact with our normalized internal API/data service.

# 25. IMPORTANT IMPLEMENTATION RULES

1. Never invent economic data.

2. Never hardcode fake production values.

3. Keep provider logic outside UI components.

4. Store raw values whenever possible and calculate display formatting separately.

5. Preserve historical observations.

6. Store source and retrieval timestamps.

7. Be explicit about seasonal adjustment.

8. Be explicit about monthly vs quarterly vs annual data.

9. Avoid comparing incompatible periods.

10. Build everything so additional indicators can be added primarily through configuration instead of creating new custom pages every time.

11. If an API requires credentials, use environment variables.

12. Never expose API keys client-side.

13. Gracefully handle unavailable government APIs.

14. A failed source should not crash the dashboard.

15. Document every external data integration.
